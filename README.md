# 麦麦攒局 · 麦当劳 MCP 聚餐众筹点餐助手

> 一群人吃麦当劳，最难的从来不是"吃什么"，而是**"谁不能吃什么"**。
> 本项目基于麦当劳官方 MCP，把「众口难调」变成一个**可复现、可解释、可回归测试**的求解问题。

**核心主张：数值不进 LLM。** MCP 只负责取真实数据（菜单 / 价格 / 营养 / 券），
所有算术与组合优化由**纯本地确定性函数**完成 —— 方案可复现、结论可解释、结果可单测。

---

## 一、它解决什么问题

| 痛点 | 本项目做法 |
|---|---|
| 5 个人 5 种忌口，手工配餐要算半天 | 多约束组合求解，秒级给出多套可行方案 |
| 素食者被推荐巨无霸、牛肉汉堡 | **隐性词穷举**词库（"巨无霸""酥酥多笋卷"这类无肉字的荤菜也拦住） |
| 想点 1+1 但默认主食是牛肉 | **换件能力**：同价位换成合规项，保住优惠不弃单 |
| 谁该付多少钱，四舍五入总差几分 | **整数分 + 余数分配**，AA 分摊总额分毫不差 |
| 一个人吃饭也想用 | **`--solo` 单人自助**：自选校验 + 自动推荐两套玩法 |
| 健康版其实是"热量数据缺失" | 营养缺失**不按 0 千卡算**，标记为"不可验证"而非假装合规 |

python feast_cli.py --demo --solo --me "我:减脂,prefer=咖啡" --solo-recommend

python selftest.py

## 三、参与者描述语法

```
"小王"                          → 无任何限制
"小王:no_beef,no_spicy"         → 用内置忌口 key
"小王:不吃牛,不要辣"              → 中文口语（自动映射）
"小王:maxcal=600,protein=30"    → 个人热量上限 / 蛋白下限
"小王:prefer=咖啡,拿铁"           → 口味偏好（同价换件时优先选中）
```

内置忌口 key：`no_beef`（不吃牛肉）、`no_pork`、`no_chicken`、`no_fish`、
`no_seafood`（不吃海鲜）、`no_fried`（不吃油炸）、`no_dairy`（不吃乳制品）、
`no_spicy`（不吃辣）、`vegetarian`（素食·蛋奶素）、`vegan`（严格素食·纯素）。

> **素食口径说明**：本项目提供**两档**素食规则，语义互不重叠 ——
> - `vegetarian`（蛋奶素）：排除肉/禽/鱼/海鲜，**保留**乳制品与蛋类
>   （芝士、新地、拿铁、蛋堡等均可吃）。
> - `vegan`（纯素）：在蛋奶素基础上**再排除**乳制品（芝士/吉士/奶/新地/麦旋风…）
>   与蛋类（蛋/蛋黄酱/沙拉酱），即一切动物性成分。
>
> 中文输入 `素食`/`蛋奶素` → `vegetarian`；`纯素`/`严格素食`/`全素` → `vegan`。

## 五、换件能力：本项目的差异化核心

麦乐送/到店菜单里，**58/63 款套餐带可换件结构**（`rounds[].choices[]`），
每个备选带 `diffPrice`（补差价，分）、`isDefault`、`quantity`、`min/maxQuantity`。

以「人气经典随心配」（1+1，¥14.9）为例，**蓝区**备选：

```
双层吉士汉堡（牛肉，默认，+¥0）
高达吉士双牛堡（牛肉，+¥0）
麦香鱼（鱼肉，+¥0）
那么大鸡排（鸡肉，-¥1）      ← 不吃牛的人应换到这个
酥酥多笋卷（鸡肉，+¥0）
麦乐鸡5块（鸡肉，-¥1）
麦香鸡（鸡肉，+¥0）
```

**没有换件能力时**：不吃牛的成员 → 这份 ¥14.9 的 1+1 整单作废。
**有了换件能力**：同价换成「那么大鸡排」，既保住优惠又满足忌口。

判定顺序本身就是设计（踩过坑）：

1. **先判换件** —— 有可换件结构就尝试为每个必选区换到合规项，能换就保留
2. **再判名称** —— 无换件空间的才按名称/标签/子项过滤
3. **疑似套餐但组成未知** → 保守排除（不能赌它含什么）
4. 单品 → 保留

> 为什么顺序关键：1+1 的**默认主食**写着"双层吉士汉堡"（牛肉）。
> 若先判名称，这个套餐在第一步就被误杀，换件能力永远用不上。

## 六、安全性设计（防漏网）

**隐性词穷举。** 麦当劳有大量「名称里一个字都不含肉」的荤菜，实测踩坑 5 次：

| 餐品名 | 实际是什么 | 名称陷阱 |
|---|---|---|
| 巨无霸 | 纯牛肉 | 无"牛"字 |
| 薄皮焦香V翅 | 鸡翅 | 无"鸡"字 |
| 不素之霸 | 双层牛肉 | 无"牛"字 |
| 吉士汉堡包 | 牛肉 | 无"牛"字 |
| **酥酥多笋卷** | **鸡肉卷** | **无"鸡"字** |

这些全部穷举进共享词表 `_MEAT_HIDDEN` / `_CHICKEN_HIDDEN` / `_BEEF_HIDDEN` …
并被 `vegetarian` 等规则复用，**不靠"肉"字兜底**。

**独立复算验证**：10 种忌口 × 全部餐品逐个展开换件结果后复检，
**737 个餐品实例，0 漏网**（见 `selftest.py` 的 [15d] 段）。

**营养诚实性**：营养数据缺失的餐品**不被当成 0 千卡**。
- 设了热量上限的人 → 缺数据候选直接拒绝（无法验证 ≠ 合规）
- 「健康版」只在全部餐品营养可验证的组合中挑选
- 换件后的营养按**实际选中的备选**重算，缺数据则显式标注"热量不可保证"

## 九、技术约束与设计取舍

- **零第三方依赖**：只用标准库（`urllib` / `ssl` / `json`），降低评委验证成本
- **金额一律整数分**：杜绝浮点误差，AA 分摊靠整数余数分配保证严格相等
- **只读设计**：不调用任何写操作的 MCP 工具，不修改任何文件
- **数值不进 LLM**：LLM 只做意图解析与结果叙述，不参与任何算术
- **诚实优先**：无法验证的（营养缺失、核价 0 元、候选被截断）一律**显式标注**，
  绝不用"看起来没问题"掩盖不确定性
