「麦麦攒局」是一个面向多人聚餐与个人控卡的麦当劳智能点餐规划器（提供命令行工具与 WorkBuddy Skill）。直接打开麦当劳 App 点餐时，组织者需要逐一询问每个人「吃不吃辣、吃不吃牛、是否减脂」，面对几十款套餐还要手动点进每个选区核对食材与补差价，既难保全套餐优惠，餐后算账还会遇到除不尽的末位分摊差额。本项目通过麦当劳官方开放平台 MCP 获取真实门店菜单、营养表与核价接口，由本地确定性组合求解算法在秒级内完成多约束匹配与套餐智能换件，并输出精确到分的 AA 分摊账单。

## 核心机制与设计考量

### 套餐换件救单机制：保住优惠，不因忌口误杀套餐
在麦当劳菜单中，多达 58 款套餐具备多选区换件结构（`rounds[].choices[]`）。
- **现实困境**：许多划算套餐的默认主食都带有肉类或辣味（例如「1+1 随心配」默认搭配常含双层吉士汉堡）。如果按套餐名称或默认项粗暴过滤，不吃牛或不吃辣的用户将直接失去这些优惠，只能单点昂贵单品。
- **解法实现**：算法采用「先遍历备选选区、再判定套餐合规」的逻辑。在备选区内搜索满足忌口的同价或补差价替换项（如将双层吉士换为那么大鸡排，将麦辣鸡腿堡换为龙焰鸡腿堡），既保证忌口合规，又保留了套餐本身的组合折扣。

### 隐性荤菜词库与两档素食防护：避开命名陷阱
麦当劳餐品命名常带有品牌化特色，常规的「牛/羊/猪/鸡/肉」字面关键词过滤极易产生安全疏漏：
- 「巨无霸」通篇无牛字，实为纯牛肉饼；
- 「不素之霸」名字带「素」，实为双层牛肉加香肠；
- 「薄皮焦香V翅」名称无鸡字，实为鸡翅；
- 「酥酥多笋卷」看似素菜卷，实为川香风味鸡肉卷。

项目建立了包含上述特异命名的隐性荤菜穷举词表，并对素食人群划分两档严密口径：
- **`vegetarian`（蛋奶素）**：排除肉、禽、鱼、海鲜，保留乳制品与蛋类（芝士、新地、拿铁等可用）；
- **`vegan`（严格纯素）**：在蛋奶素基础上进一步排除一切乳制品与蛋制品。  
该逻辑在 737 个真实餐品实例的全量展开测试中维持 0 漏网记录。

### 营养核算与缺失标记：拒绝将缺失项当作零热量
麦当劳官方接口中部分促销餐品或组合套餐并未在单品表中附带热量数值。
- **设计底线**：若餐品缺失营养数据，系统绝不将其视为 0 千卡，避免高油高糖餐品被算法钻空子推给控卡用户。
- **透明标注**：凡组合中含有未核验餐品，方案均显式附加 `⚠ 含营养数据缺失项，热量不可保证` 告警；减脂用户的严格候选池绝不吸纳未核验餐品；「轻负担健康版」策略优先在全量数据可信的组合中进行能质比优化。

### 确定性整数分 AA 分摊：消除浮点误差与末位差额
多人聚餐总额除以人数经常产生无限循环小数（如 41.80 元分给 3 人，人均 13.9333... 元）。
- 浮点数计算极易出现舍入飘移；
- 本项目全程采用整数「分」进行记账与分配，余数通过确定性序号分配给前序参与者（例如两人 13.93 元、一人 13.94 元）；
- 严格保证每一分钱都有据可循，`sum(应付) == 订单总额`，消除算账时的几分钱差额纠纷。

### 单人 1+1 随心配自助：冲突直观标红与低卡组合推荐
除了多人攒局，单人就餐同样需要避坑与算账：
- **备选看板**：`--solo` 模式可清晰展示当前红蓝选区，对与个人忌口冲突的选项直接以 `✗` 标红，并列出差价；
- **手选校验**：通过 `--pick "蓝区=xxx,粉区=yyy"` 传入意向代码，即时核算实付并检测是否有隐性冲突；
- **智能推荐**：`--solo-recommend` 结合个人热量上限与口味偏好（如 `--me "我:减脂,prefer=咖啡"`），自动推选合规且营养均衡的组合。

### 门店定位、优惠券与下单链路：明确写操作安全边界
系统打通了从周边搜索到订单建立的完整交互链路：
- **门店搜索**：支持 `--city` 与 `--keyword` 定位附近餐厅，或 `--favorites` 查收藏门店；
- **三类券口径分清**：区分「门店可用券」（已结合当前门店校验，下单真实可用）、「卡包券」（已拥有但未校验门店）与「可领取券」（当前可领但尚未领取）；
- **写操作必须显式确认**：只读工具自动执行，而系统仅有的两个写操作（`--order` 创建订单、`--bind-coupons` 一键领券）**默认不执行**。`--order` 默认仅打印预演报文（DRY-RUN），`--bind-coupons` 未加确认直接拒绝，均必须追加 `--confirm` 才会发起调用；
- **无独立支付工具声明**：麦当劳 MCP **没有独立支付工具**，本项目的能力止于「创建订单（待支付）」，**不代收款项、不代付款**。支付须在麦当劳官方 App/小程序完成，之后可通过 `--pay-status --order-id <订单号>` 查询核对状态；
- **渠道取餐编码规则**：到店自取（`beType=1`）门店**不返回** `beCode`，后续调用不得传；得来速（`beType=5`）返回 `beCode`，后续调用必须传。

## 架构决策与设计取舍

### 为什么坚持「数值与约束不进大模型」？
大语言模型擅长提取非结构化语言意图（例如将「我想控卡、不吃辣、喜欢喝咖啡」转化为参数结构），但在执行笛卡尔积组合搜索、硬约束校验以及金额分摊时极易产生幻觉与算术偏差。  
本项目确立了明确的技术分工：
- **LLM / WorkBuddy 技能层**：负责用户意图提取与自然语言交互；
- **本地确定性 Python 引擎**：负责所有的菜品过滤、换件递归、组合求解、热量核算、整数分 AA 分摊与官方核价。方案计算过程完全确定、可复现、可测试。

### 纯标准库零依赖实现
核心求解器及客户端仅依赖 Python 标准库（`urllib`、`ssl`、`json`、`argparse`、`dataclasses`、`itertools`），无需运行 `pip install`，无外部 C 扩展。环境部署轻量，便于评委与开发者即时验证。

### 诚实面对已知限制与工程取舍
1. **优惠券不参与求解择优**：优惠券的满减阶梯、互斥规则及特定品类限制难以仅凭客户端数据做可靠推断。为避免给用户给出无法核验的「虚假低价」，本项目不把优惠券作为求解优化变量，而是作为下单参数透传，最终价格以官方 `calculate-price` 的权威核价为准。
2. **详情拉取量受限**：为了避免全量拉取对官方 MCP 造成调用压力（单次全流程约调用 100~110 次），系统默认限制详情拉取数量（`--max-detail 60`），并在命令行中显式打印菜单覆盖率，杜绝将「未覆盖餐品」掩盖为「预算内无解」。
3. **官方接口能力边界**：严格遵守官方 MCP 暴露的接口范围，不包装不存在的支付能力，保持审慎求实。

### 真实 MCP 模式（连接麦当劳开放平台）

在 [麦当劳开放平台](https://open.mcd.cn/mcp) 申请开发者 Token 后，设置环境变量即可连通线上接口：

```bash
# 环境变量配置（Linux / macOS）
export MCD_MCP_TOKEN=你的Token
# Windows PowerShell
$env:MCD_MCP_TOKEN="你的Token"

# 1. 搜索附近门店（获取 storeCode）
python feast_cli.py --stores --city "上海市" --keyword "人民广场"

# 2. 查询该门店可用券 / 我的卡包券 / 当前可领券
python feast_cli.py --coupons --store-code <storeCode>
python feast_cli.py --coupons --my-coupons
python feast_cli.py --coupons --available

# 3. 真实在线多人配餐规划
python feast_cli.py --city "上海市" --keyword "人民广场" --budget 50 \
    --people "我:减脂,protein=25" "小王:不吃牛"

# 4. 创建订单：默认 DRY-RUN 仅打印提交报文；确认无误后追加 --confirm 真实下单
python feast_cli.py --order --store-code <storeCode> --take-way-code <取餐码> \
    --people "我:减脂" "小王:不吃牛"
python feast_cli.py --order --store-code <storeCode> --take-way-code <取餐码> \
    --people "我:减脂" "小王:不吃牛" --confirm

# 5. 复核支付状态（在官方渠道完成支付后查询）
python feast_cli.py --pay-status --order-id <订单号>
```

## 麦当劳 MCP 接入流程与链路

### 求解与核价链路（只读）
```text
[1] query-nearby-stores      按城市与地标定位门店，获取 storeCode 与 beCode
[2] query-meals              拉取门店当前可用餐品编码与品类标签
[3] query-meal-detail        批量拉取餐品名称、组成明细与 rounds[].choices[] 换件树
    list-nutrition-foods     拉取官方全量食品营养成分表（千卡/蛋白质/脂肪/钠）
    calculate-price          补充核算未标价单品的基准价格
[4] 本地确定性求解引擎        执行多约束组合搜索、忌口过滤、换件救单与 AA 分摊
[5] calculate-price          提交最终组合方案至官方接口，完成权威核价校验
```

### 券与下单链路（写操作严格受控）
```text
query-store-coupons          门店维度可用券（已校验门店/渠道/配送规则，下单用这个）
query-my-coupons             卡包已拥有的券（不做门店校验，能否使用以下单结果为准）
available-coupons            当前可领取的券（展示状态与有效期）
auto-bind-coupons            一键领券 —— 写操作，未加 --confirm 时程序直接拒绝
create-order                 创建订单 —— 写操作，默认 DRY-RUN，需 --confirm
query-order / order-list     订单查询与支付状态复核（官方渠道支付后查询）
```

详细的接口协议交互细节与联调避坑记录参见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。
