# 麦麦攒局 · 麦当劳 MCP 聚餐点餐助手

## 适用场景

当用户需要在麦当劳点餐或聚餐，且有以下诉求时使用：

- 多人拼单：各人有不同忌口（不吃牛/猪/鸡/海鲜/辣/油炸）或饮食习惯（蛋奶素/纯素）。
- 减脂控卡：需要限制单人热量（如 ≤600 kcal）或保证高蛋白（如 ≥30g 蛋白质）。
- 套餐换件：想要套餐优惠，但默认主食踩了忌口，希望自动在备选区换成合规项。
- 精确 AA：需要将整单总额分摊到每个人，账单精确到分且总和分毫不差。
- 单人 1+1 自助：查询当期随心配组合，校验忌口冲突，或由算法推荐低卡/高蛋白搭配。
- 真实数据接入：基于麦当劳官方开放平台 MCP 获取实时门店菜单、营养表与权威核价。

## 核心设计

所有数值运算、菜单过滤、组合优化与账单分摊全部由本地确定性 Python 函数完成，LLM 仅负责意图提取与自然语言交互，避免大模型算术幻觉与金额误差。

## 环境要求

- Python 3.8+（纯标准库，无任何第三方依赖）
- 离线演示：无需任何配置，内置 107 餐品 / 63 套餐真实快照
- 真实调用：设置环境变量 `MCD_MCP_TOKEN`（在 https://open.mcd.cn/mcp 获取）

## 快速调用

脚本目录（相对本 SKILL.md 所在目录）：`scripts/`

- 用户级安装（默认）：`C:\Users\<用户名>\.workbuddy\skills\mcd-feast-planner\scripts\`
- 项目内安装：`<项目根>\skills\mcd-feast-planner\scripts\`

下文示例均假设当前目录已切换到该 `scripts/` 目录；若需在别处调用，请使用上述绝对路径。

### 1. 多人聚餐（含减脂、忌口、素食）

```bash
# 离线演示模式（秒级出方案）
python feast_cli.py --demo --budget 60 \
    --people "我:减脂,prefer=咖啡" "小王:不吃牛,不要辣" "小张:素食"

# 真实 MCP 调用模式
python feast_cli.py --city <城市> --keyword <地标名> --budget 50 \
    --people "我:减脂,protein=25" "小王:不吃牛"
```

### 2. 单人 1+1 随心配自助

```bash
# 查看备选看板与忌口冲突标注
python feast_cli.py --demo --solo --me "我:不吃牛"

# 手选组合并校验价格与合规性
python feast_cli.py --demo --solo --me "我:不吃牛" \
    --pick "蓝区=521816,粉区=3050"

# 自动推荐低卡/偏好搭配
python feast_cli.py --demo --solo --me "我:减脂,prefer=咖啡" --solo-recommend
```

### 3. 参与者语法与饮食约束

```text
"小王"                          无限制
"小王:减脂"                      自动设热量上限 650 kcal
"小王:高蛋白"                    自动设蛋白下限 30g
"小王:maxcal=550,protein=25"    精确指定热量上限与蛋白下限
"小王:不吃牛,不要辣"              中文口语映射
"小王:prefer=拿铁,咖啡"          口味偏好，同价换件时优先选中
```

内置忌口标签：
- 肉类与海鲜：`no_beef`、`no_pork`、`no_chicken`、`no_fish`、`no_seafood`
- 口味与加工：`no_spicy`、`no_fried`、`no_dairy`
- 素食两档口径：
  - `vegetarian`（蛋奶素）：排除肉/禽/鱼/海鲜，保留乳制品与蛋类（芝士、新地、拿铁等可用）
  - `vegan`（严格纯素）：在蛋奶素基础上再排除乳制品与蛋类

## 模块结构

| 文件 | 核心职责 |
|---|---|
| `mcd_client.py` | 麦当劳 MCP HTTP 客户端（仅标准库 urllib + ssl + json） |
| `normalize.py` | 接口数据归一化、营养表多级回退匹配、套餐换件结构解析 |
| `feast_solver.py` | 数据模型、忌口词表、隐性词库、组合换件判定、整数 AA 分摊 |
| `feast_engine.py` | 多人组合搜索引擎、多策略择优（性价比 / 轻负担 / 豪华） |
| `solo_engine.py` | 单人 1+1 识别、备选区冲突标注、手选校验、智能推荐 |
| `feast_cli.py` | 统一命令行交互入口 |
| `selftest.py` | 离线自动化测试套件（239 条断言） |

## 关键设计约定

1. **先换件再判名称**：套餐默认项经常带有荤菜主食（如 1+1 默认主食是双层吉士汉堡），若先判套餐名称会误杀整个优惠。算法优先检查选择区能否换成合规餐品。
2. **隐性荤菜词库防护**：对「巨无霸」「不素之霸」「薄皮焦香V翅」「酥酥多笋卷」等名称不含肉字的餐品建立专有穷举词库，杜绝漏网。
3. **真实营养核验**：缺失营养数据的餐品不按 0 千卡计算。设了热量上限的人选不到未核验餐品；「轻负担健康版」优先在全量数据可信的组合中挑选。
4. **整数分记账**：金额全流程以「分」存储，分摊余数按确定性规则分配，避免浮点数舍入误差。
5. **写操作默认不执行**：只读工具自动调用；`create-order`（下单）与
   `auto-bind-coupons`（领券）两个写操作**默认 DRY-RUN 或直接拒绝**，
   必须用户显式加 `--confirm` 才会真正提交；本技能**不代付款**。
   本地不保存任何明文凭据（Token 走环境变量或本机 DPAPI 密文，不入仓库）。

## 门店 / 券 / 下单 速查

| 目的 | 命令 | 性质 |
|---|---|---|
| 搜附近门店 | `--stores --city <城市> --keyword <地标>` | 只读 |
| 查收藏门店 | `--stores --favorites` | 只读 |
| 门店可用券（下单用） | `--coupons --store-code <storeCode>` | 只读 |
| 我的卡包券 | `--coupons --my-coupons` | 只读 |
| 可领取的券 | `--coupons --available` | 只读 |
| 一键领券 | `--bind-coupons --confirm` | **写操作** |
| 创建订单 | `--order ... --confirm` | **写操作**（默认 DRY-RUN） |
| 支付状态复核 | `--pay-status --order-id <订单号>` | 只读 |

> ⚠️ 到店自取（`beType=1`）门店**不返回** `beCode`，后续调用不得传；
> 得来速（`beType=5`）返回 `beCode`，后续调用必须传。
> ⚠️ 麦当劳 MCP **无独立支付工具**，能力止于「创建订单（待支付）」。
