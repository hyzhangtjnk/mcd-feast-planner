# 麦麦攒局 · 麦当劳 MCP 聚餐点餐助手

## 何时使用本技能

用户提到以下任一场景时使用：

- 一群人吃麦当劳，需要根据各自的忌口/热量目标/预算配餐
- 需要对聚餐订单做 AA 精确分摊
- 单人想点「1+1 随心配」，希望自己选或让工具推荐
- 需要把套餐里不合忌口的默认项**换成**合规项（换件）
- 需要基于麦当劳 MCP 做真实菜单/价格/营养查询

## 核心主张

**数值不进 LLM。** LLM 只负责意图解析与结果叙述；
所有菜单处理、价格计算、组合优化、AA 分摊 **全部由本地确定性函数完成**。
这样每个方案都可复现、可解释、可回归测试。

## 环境要求

- Python 3.8+（**零第三方依赖**，仅标准库）
- 真实调用需 `MCD_MCP_TOKEN` 环境变量（申请：https://open.mcd.cn/mcp）

## 用法

工作目录：`skills/mcd-feast-planner/scripts/`

### 多人聚餐

```bash
# 离线演示（无需 Token）
python feast_cli.py --demo --budget 60 \
    --people "我:减脂" "小王:不吃牛,不要辣" "小李:素食"

# 真实调用
export MCD_MCP_TOKEN=你的token
python feast_cli.py --city <城市> --keyword <地标名> --budget 50 \
    --people "我:减脂" "小王:不吃牛" --verbose

# JSON 输出
python feast_cli.py --demo --json
```

### 单人 1+1 自助

```bash
# 看备选面板（标出与忌口冲突的项）
python feast_cli.py --demo --solo --me "我:不吃牛"

# 手选 + 实时校验
python feast_cli.py --demo --solo --me "我:不吃牛" \
    --pick "蓝区=521816,粉区=3050"

# 自动推荐
python feast_cli.py --demo --solo --me "我:减脂,prefer=咖啡" --solo-recommend
```

### 参与者语法

```
"小王"                          无限制
"小王:no_beef,no_spicy"         忌口 key
"小王:不吃牛,不要辣"              中文口语（自动映射）
"小王:maxcal=600,protein=30"    热量上限 / 蛋白下限
"小王:prefer=咖啡,拿铁"           口味偏好（同价换件时优先）
```

忌口 key：`no_beef` / `no_pork` / `no_chicken` / `no_fish` / `no_seafood` /
`no_fried` / `no_dairy` / `no_spicy` / `vegetarian`（蛋奶素）。

### 常用参数

| 参数 | 说明 |
|---|---|
| `--budget N` | 人均预算（元） |
| `--be-type N` | 1-到店自取 2-麦乐送 5-得来速 6-团餐 |
| `--order-type N` | 1-到店 2-外送 |
| `--max-detail N` | 最多取多少个餐品详情（默认 60） |
| `--max-price-fill N` | 最多补多少个餐品价格（默认 40） |
| `--no-price-fill` | 跳过价格补齐 |
| `--verbose` | 打印被跳过餐品的原因 |

## 模块职责

| 文件 | 职责 |
|---|---|
| `mcd_client.py` | 麦当劳 MCP 最小 HTTP 客户端（零依赖） |
| `normalize.py` | 原始返回 → 求解器输入（含套餐换件解析、营养匹配） |
| `feast_solver.py` | 数据模型 + 忌口规则 + 换件逻辑 + AA 分摊 |
| `feast_engine.py` | 多人组合求解引擎（枚举 / 策略择优） |
| `solo_engine.py` | 单人 1+1 自助（自选校验 / 自动推荐） |
| `feast_cli.py` | 命令行入口 |
| `selftest.py` | 离线自测（146 断言） |

## 输出内容

每次求解输出多套方案（性价比 / 健康 / 豪华），每套包含：

- 每人具体吃什么（套餐会展开显示**实际组成**，含换件结果）
- 总价、人均、总热量、人均蛋白
- 换件明细（为忌口换掉了什么、补差价多少）
- AA 分摊表（整数分，总额分毫不差，附分摊校验）
- 价格核验状态（未通过会显式标注）

## 重要设计约定

1. **换件判定顺序**：先判是否可换件，再判名称。
   因为套餐默认项常写着默认主料（如 1+1 默认「双层吉士汉堡」是牛肉），
   先判名称会把可救的套餐误杀。

2. **隐性词穷举**：`巨无霸`、`薄皮焦香V翅`、`酥酥多笋卷`（鸡肉卷）等
   名称里不含肉字，必须逐条穷举进词表，**不能靠"肉"字兜底**。

3. **营养缺失不等于 0 千卡**：设了上限的人，缺数据候选直接拒绝；
   「健康版」只在营养全部可验证的组合中挑选。

4. **素食口径 = 蛋奶素**：同时排除乳制品与蛋类。严格纯素可叠加 `no_dairy`。

5. **只读**：不调用任何写操作 MCP 工具，不修改任何文件。

6. **诚实标注**：核价返回 0、营养缺失、菜单截断，一律显式告警。
